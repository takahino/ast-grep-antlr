ast-grep vs ag4

Snapshot as of 2026-10-25: upstream @ast-grep/cli@0.51.0 vs ag4 on pinned corpora and shared patterns. Default backend is tree-sitter (including C#); ANTLR / Roslyn numbers are opt-in.

Current stance: Java / C++ / Python / C# default to tree-sitter. Unexplained diffs are 0 after known-differences.yml. Matching upstream’s hit set 100% is not a goal. ag4’s edge is in-process .NET, NativeAOT DLL, and ANTLR .g4 (including languages upstream lacks).

1. Setup

  • Harness: tools/AstGrepAntlr.DiffTest
  • Languages: Java / C++ / C# / Python (PL/SQL: no upstream language — “—” in tables)
  • Corpora: commons-lang, java-design-patterns, google-java-format, leveldb, cereal, fmt, Newtonsoft.Json, Humanizer, serilog, click, attrs, flask (pinned tag/SHA)
  • Patterns: calls, $$$, statements, composites, rewrites
  • Tables: difftest/REPORT.md
ag4 languages: Java / C++ / Python / C# = tree-sitter default. ANTLR via --backend antlr (Java/C++/Python); Roslyn via --backend roslyn (C#). PL/SQL & SQLite are ANTLR. Custom DSLs via sgconfig.yml customLanguages.

4. Parse performance

Matching is cheap; parse dominates.

Target parse Notes
Java · tree-sitter (commons-lang 264) ~0.67s native ≈ arena build; diag walk ≈ 0 when root has no error
Java · ANTLR (same) ~1.4s 2% LL fallback (4/264), down from 67% after the classType grammar fix
C# · tree-sitter (corpus 1587) ~4.4s cursor walk + cheaper P/Invoke; match is a few percent
C++ · ANTLR (leveldb 131) ~7s 73% LL fallback; grammar fix halves each LL pass (~13s → ~7s). Main reason difftest is so slow

Startup (10-run avg, win-x64): NativeAOT ≈ 42ms, JIT dotnet ag4.dll ≈ 254ms. Release exe is AOT. Languages register lazily. Prefer DLL / NuGet / MCP to keep ANTLR DFAs warm.

Most LL fallbacks are not “syntax-error recovery”: valid input still fails SLL prediction and retries in LL. Reducing that rate is mostly a grammar / ambiguity problem.

5. When to use what

Need Prefer
Upstream-like search (Java / C++ / Python / C#) Upstream, or ag4 with tree-sitter default
ANTLR grammars / custom DSL / languages upstream lacks ag4 (ANTLR / .g4)
In-process .NET, NativeAOT DLL, MCP ag4
Roslyn CST for C# ag4 --backend roslyn (lower match rate vs upstream)

6. Typical remaining gaps

Still present on tree-sitter defaults

  • Single-child unwrap, modifier skipping, extras (comments)
  • ag4 MetaVarVariants placeholder expansion
  • Same hit, different metavar span (especially C#)

With ANTLR

  • ag4 broader call patterns often include ctor / this / super
  • upstream broader complex methods, modern C++, Python indentation — grammar limits

With Roslyn (C#)

  • Paren expressions vs casts, identifier granularity, brace shapes
  • CST drift vs tree-sitter-c-sharp drives ~53% match rate
