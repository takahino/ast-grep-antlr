ast-grep vs ag4 differences

Summary of comparing upstream @ast-grep/cli@0.51.0 (tree-sitter) with ag4 (tree-sitter default for Java/C++/Python/C#; optional ANTLR or Roslyn) on real corpora. Remaining gaps are mostly matcher logic, not engine bugs.

Policy: ag4 bugs (encoding, exit codes, byteOffset, pattern compile failures, etc.) were fixed. With tree-sitter as the default backend, kind names align with upstream; residual diffs are matcher behaviour and Roslyn vs tree-sitter-c-sharp when --backend roslyn is used. ANTLR/Roslyn CST drift is catalogued in difftest/known-differences.yml (optional backend: field). Matching upstream’s hit set 100% is not a goal.

1. Comparison setup

  • Harness: tools/AstGrepAntlr.DiffTest
  • Numbers on this page cover Java / C++ / C# / Python (languages with upstream counterparts and pinned corpora). PL/SQL has no upstream language — the table shows “—” (not available)
  • Corpora: commons-lang / java-design-patterns / leveldb / cereal / fmt / Newtonsoft.Json / Humanizer / click / attrs (pinned tag + SHA)
  • Patterns: calls, $$$, statements, composite rules (no kind), rewrites — ~55 per language
  • Full report: difftest/REPORT.md
ag4 built-in languages (current): Java / C++ / Python / C# (tree-sitter default); Java / C++ / Python also support ANTLR; C# supports Roslyn; PL/SQL & SQLite are ANTLR. Custom DSLs via sgconfig.yml customLanguages (.g4 / .interp). Difftest accepts --backend.

3. How to read “accuracy”

ast-grep’s primary goal is finding/rewriting code that matches a structural pattern as intended. The de facto ground truth for that semantics is the tree-sitter pattern model.

Use case Better fit
Same feel as upstream (Java / C++ / Python, tree-sitter default) Upstream or ag4 (tree-sitter) — kinds align; matcher gaps remain
ANTLR grammars, custom DSLs, languages upstream lacks (e.g. PL/SQL, SQLite, custom .g4) ag4
C# (Roslyn CST) ag4 (Roslyn) / upstream (tree-sitter-c-sharp) — aliases absorb some gaps
Extending .g4 helps ANTLR parse coverage (especially C++). It does not erase CST shape differences. Prefer tree-sitter default when you want upstream-like kinds.

4. Typical differences (examples)

Often reduced with tree-sitter default

  • Kind-name mismatch (e.g. methodDeclaration → method_declaration)
  • ANTLR grammar limits (modern C++, Python indent blocks)

Remaining when using ANTLR (examples below are ANTLR baseline)

ag4 broader Over-match on $F($$$ARGS)

Intent (upstream-ish): ordinary method calls. ag4 more readily matches call-like shapes. 

foo(1, 2);      // both usually hit
obj.bar(x);

new Foo(1, 2);  // ctor-like tree → ag4 often hits
this(1);        // explicit this
super(x);       // explicit super

On difftest call-any (commons-lang): same ≈ 1 957 vs only-ag4 ≈ 6 293.

upstream broader Misses on public $TYPE $NAME($$$PARAMS) { $$$BODY }

Intent: public methods with bodies. ag4 tends to miss non-simple shapes.

public int run(int x) { return x; }   // both usually hit

public void run() { }                 // void often poor fit for $TYPE
public <T> T id(T x) { return x; }  // type params
public int f() throws IOException { return 0; }
@Override
public String toString() { return ""; }

On difftest public-method: same ≈ 290 vs only-ast-grep ≈ 1 450 (ag4 misses).

Other common drifts (ANTLR / Roslyn)

  • Java · only upstream: import/package splitting, annotations, multi-catch / try-with-resources, diamond / anonymous new, some if-blocks
  • Java · only ag4: this/super calls (upstream patterns often ERROR), lambda / method-ref, some for / class-body shapes
  • Metavars: same match, different capture text/range from CST wrapping (large volume)
  • C++ · only upstream: modern syntax / macros that ANTLR CPP14 cannot parse well (main match-rate drag)
  • C++ · only ag4 (few): qualified ctors (e.g. std::string(...)), std::move, namespace/class bodies, etc.
  • C# · only upstream: parenthesized expressions treated as casts, finer identifier granularity, await / lambda / typeof·nameof, …
  • C# · only ag4: braced if/for/while/foreach and public $T $N(...)-style patterns that Roslyn matches more readily

Still present with tree-sitter (matcher logic)

  • Single-child unwrap, modifier skipping, extra (comments) handling
  • MetaVarVariants and other ag4-only placeholder expansion
  • Metavar capture span drift even when the hit range matches

5. Aligned behavior (not “differences”)

  • Exit codes (run 0/1/2, scan --error-on)
  • Encoding / BOM preservation, --encoding
  • JSON 0-based line/column, real-file byteOffset
  • stopBy default neighbor, precedes/follows
  • gitignore, globs, hidden-file defaults
  • Statement-pattern compile failures (if / for / try, …) largely fixed
  • Kind names match upstream (Java / C++ / Python tree-sitter default)
  • --backend / languageBackends to keep ANTLR kinds
