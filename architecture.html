ag4 アーキテクチャ

ast-grep-antlr（ag4）の内部構造を、データの流れに沿ってまとめた資料です。対象は working tree の現状（Java / C++ / Python は tree-sitter 既定、PL/SQL / SQLite / DSL は ANTLR、C# は Roslyn）で、記載したクラス名・ファイルはすべて src/ 配下に実在します。

1. 概要と設計方針

ag4 は ast-grep 互換の構造検索・書き換えツールです。主要言語（Java / C++ / Python）はtree-sitter（既定）で解析し、本家に近い kind 名と速度を狙います。PL/SQL ・SQLite・独自 DSL は ANTLR4 です。C# も既定は tree-sitter で、--backend roslyn により Roslyn に切り替えられます。--backend / languageBackends で Java / C++ / Python を ANTLR に戻せます。.NET 10 で実装しています。

  • ast-grep 互換の外部仕様 — CLI のサブコマンド、YAML ルールのスキーマ、JSON 出力のフィールド（0 始まりの range、metaVariables など）、終了コードを揃える。
  • 文法は差し替え可能 — 照合エンジンはパーサ固有の型を知らず、共通のアリーナ木 SyntaxTree だけを見る。言語は ILanguage を実装すれば追加できる。
  • ハイブリッドバックエンド — 速度・本家互換は tree-sitter、BNF / 独自 DSL は ANTLR、現行 C# 仕様追従は Roslyn。
  • 構文エラーがあっても止まらない — tree-sitter は ERROR/MISSING を木に残す。ANTLR は SLL → LL + エラー回復。
  • 文字コードを壊さない — Shift_JIS / EUC-JP / UTF-16 / BOM 付きファイルも、検出した文字コードのまま書き戻す。
  • 独自 DSL — .g4 / .interp を sgconfig.yml に書けば、ビルドし直さずに使える。

3. 検索パイプライン

ag4 run も ag4 scan も、MCP の find_code も、最後は Searcher の同じ処理にたどり着きます。パターンのコンパイルは 1 回だけ行い、ファイルごとの処理は並列に実行します。

  • Searcher.RunPattern（パターン）、RunRule（YAML ルール）、RunPatternOnSources（ディスクを読まずにメモリ上のバッファを検索）の 3 つの入口は、どれも SearchFiles / SearchSources → CollectMatches という同じ流れを通ります。
  • MaxFileBytes（組み込み言語は 8 MiB、.interp 言語は 4 MiB）を超えるファイルは読みません。読込やパースの失敗は、run --show-errors で ShowErrors が有効なときだけ ag4: skip … として stderr に出します。
  • FileWalker は bin / obj / node_modules を常に除外します。.gitignore は親ディレクトリから git ルートまで、さらに .git/info/exclude も読み込みます（GitIgnoreMatcher：後に書かれたパターンが優先、否定パターン対応）。

4. 言語フロントエンド層

設計判断：tree-sitter の採用と ANTLR / Roslyn の併存 Java / C++ / Python は本家 ast-grep と同じ tree-sitter 文法を既定にし、速度と kind 名の互換を優先します（TreeSitterLanguage + TreeSitterTreeBuilder）。PL/SQL・SQLite・独自 DSL は BNF（g4）で拡張したいため ANTLR のままです。C# の既定も tree-sitter-c-sharp で、Roslyn（LanguageVersion.Latest）は --backend roslyn で選べます。ILanguage はパーサに依存しないので、照合エンジンを変えずにバックエンドだけ差し替えられます。--backend antlr / languageBackends で旧 ANTLR kind のルールも維持できます。

組み込み言語

id 別名 拡張子 ルート kind / StartRule 既定バックエンド
java .java program（ANTLR 時 compilationunit） tree-sitter-java（切替可）
cpp c++, cc, cxx .cpp .cc .cxx .c++ .hpp .hh .hxx .h translation_unit（ANTLR 時 CPP14 translationUnit） tree-sitter-cpp（切替可）
csharp cs, c# .cs compilation_unit tree-sitter-c-sharp（切替可 → Roslyn）
python py .py module（ANTLR 時 file_input） tree-sitter-python（切替可）
plsql pl/sql .pls .pkb .pks .sql sql_script grammars-v4 sql/plsql (Apache-2.0)
sqlite .sql .sqlite parse grammars-v4 sqlite

.sql は PL/SQL と SQLite の両方に登録されているので、どちらとして扱うかは -l で指定します。文法のライセンスは THIRD-PARTY-NOTICES.md と各 grammars/*/LICENSE を参照してください。

LanguageRegistry

  • Register：インスタンスをすぐに登録します（組み込み言語）。
  • RegisterLazy：生成関数だけを登録し、最初の Get で実体を作ります。run -l java のときに、sgconfig に書かれた無関係な DSL 文法までコンパイルしないための仕組みです。生成関数はロックの外で呼ぶので、別名経由で Get が入れ子になってもデッドロックしません。
  • RegisterAlias：c++ → cpp のような別名を、登録済みの言語にも遅延登録の言語にも張れます。バックエンド切替時は BuiltinLanguages.ApplyBackend が別名を再登録します。
  • BuiltinLanguages.ApplyBackend / ApplyBackends：Java / C++ / Python を tree-sitter と ANTLR の間で差し替えます。ネイティブが読めないときは ANTLR にフォールバックします。

独自 DSL（customLanguages）

.interp による解釈実行では、文法に書かれたアクションと述語（{…}?）は実行されません。述語に頼る文法（Python の INDENT/DEDENT など）は、組み込み言語として C# の LexerBase / ParserBase と一緒に生成する必要があります。

5. パース（ANTLR 2 段階 / tree-sitter）

ANTLR 系は下記の SLL → LL です。tree-sitter 系（TreeSitterLanguage）は UTF-16LE で ts_parser_parse_string_encoding を呼び、スレッドごとに parser を保持して並列検索に耐えます。ERROR / MISSING から ParseDiagnostic を集め、アリーナ変換後にネイティブ木を解放します。パターン片は文脈テンプレート（例: class __AG4 { void __m() { {0} } }）に埋め込んでパースし、埋め込み範囲と一致するノードを取り出します。

パターン片の解析（AntlrPatternParser.TryParseFragment）は Bail 戦略だけを使い、SLL → LL の順に試します。入力を EOF まで読み切れなかった場合は失敗（null）とします。ソース側は「多少壊れていても解析を続ける」、パターン側は「厳密に解析できたものだけ採用する」という非対称な方針です。

6. アリーナ構文木

ANTLR の IParseTree（オブジェクトのグラフ）は TreeBuilder が SyntaxNode[] の配列（アリーナ）に変換します。親・最初の子・次の兄弟は配列のインデックスで指すので、照合中のポインタ追跡や割り当てを減らせます。

フィールド 意味
Kind Rule / Token / Error / Missing
TypeId, TypeName ルール名またはトークンの記号名（kind 照合に使う）
Start, End デコード後の文字列での UTF-16 オフセット（開始は含み、終了は含まない）
Parent, FirstChild, NextSibling, ChildCount インデックスで木を表すリンク（存在しなければ -1）
IsNamed tree-sitter の named / anonymous に相当。( のような記号は unnamed
IsExtra tree-sitter の extra（コメントなど）。cst 以外の strictness では子選択時に除外
ChainHead 単一子チェーンの先頭ノードのインデックス（ANTLR 向け畳み込み）
MetaVarName, IsMultiMetaVar, MetaVarTypedRule パターン木でだけ使う。メタ変数の印
  • ANTLR の CharStreams.fromString はコードポイント単位のオフセットを返すため、TreeBuilder は UTF-16 への対応表を作ります。サロゲートペアを含まない入力では対応表を作らず、オフセットをそのまま使います。tree-sitter は UTF-16LE バイト単位なので、バイトオフセット ÷ 2 がそのまま UTF-16 文字オフセットです。単一子チェーンの畳み込みは ANTLR 向け（tree-sitter では無効）。supertype は別名として kind 索引に登録します。
  • kind ごとの索引（_kindIndex）には型名・別名・ERROR を登録します。chainKinds は分割済みの配列で持ちます。KindMatches はすべての木の全ノードに対して呼ばれる最も実行回数の多い処理なので、そこで文字列を分割して割り当てが起きないようにするためです。

7. パターンコンパイル

  1. シードプラン：全メタ変数を {0} にする案、$$$ を文にする案、名前から推測する案（BODY / TRY / CATCH を含む名前は文、ARG / PARAM を含む名前は int {0}）を先に試します。
  2. オドメータ：シードで解析できなければ、右端のメタ変数から順に置換形を切り替えて総当たりします（入れ子の本体ほど先に変わります）。
  3. 印付け：挿入したテキストとスパンが完全に一致するノードのうち最も外側のものに印を付け、トークンだけが見つかった場合は単一子チェーンを上にたどります。これで ${A:expression} のような型付きメタ変数が式チェーンの先頭に付きます。印を付けられないメタ変数が残った組み合わせは不採用です。
  4. ルートの確定：DescendPatternRoot で、意味のある子が 1 つしかない間は下に降ります（<EOF> は無視）。context と selector を指定した場合は、selector の kind に一致するノードをルートにします。
  5. 必須リテラル：プレースホルダ以外の名前付きトークンで 2 文字以上のものを RequiredLiterals にします。

8. マッチング

PatternMatcher.MatchAll は、パターンのルートの kind に一致する対象ノード（NodesMatchingKind）を候補にします。ルートがメタ変数の場合は全ノードが候補です。同じ範囲にヒットした結果は 1 件にまとめます。

  • 単一子アンラップ：kind が一致しなくても、対象かパターンの片方が子を 1 つだけ持つなら、1 段降りて照合し直します（cst 以外）。
  • smart での読み飛ばし：対象側にだけある unnamed トークンや、メタ変数の直前にある修飾子（final / public / variableModifier など）は読み飛ばします。そのため catch ($E $N) が catch (final Exception e) にもヒットします。
  • B6 リストガード：パターン側のメタ変数ノードが kind K の子を 1 つだけ持つのに、対象側の同じ kind のノードが K の子を 2 つ以上持つ場合は不一致にします（$A が引数リスト全体を飲み込むのを防ぎます）。
  • 型付きメタ変数：${A:expression} は、照合時に KindMatches(node, "expression") を追加で検査します。
Strictness 比較する子 kind の一致 対象側の余分な子
cst 全トークン 必須（不一致なら即失敗） 許さない
smart（既定） 全トークン（対象側の unnamed は読み飛ばし可） 必須（単一子アンラップで救済） unnamed のみ許す
ast named のみ 必須（単一子アンラップで救済） 末尾の余りを許す
relaxed named のみ 検査しない 末尾の余りを許す

9. YAML ルールエンジン

RuleLoader（YamlDotNet）がルール YAML を SgRuleDocument / RuleNode に、sgconfig.yml を SgConfig に読み込みます。RuleEngine.MatchRule は RuleNode を再帰的に評価します。

種類 評価方法
all 各分岐の結果を、ソース範囲 (Start, End) をキーにした積集合にする
any 各分岐の結果を範囲で重複を除いて和集合にする
not スコープ内の全ノードから、内側の規則の結果を引いた補集合（メタ変数は持たない）
matches utils の規則を名前で参照する（sgconfig の utilDirs とルール内の utils をマージし、ルール側を優先）
constraints マッチした後で、取り込んだメタ変数に kind / regex の条件を検査する
  • コンパイル済みパターンのキャッシュ：(LanguageId, PatternSpec) をキーに ConcurrentDictionary に保存します。パターンはファイルに依存しないので、N 個のファイルを scan してもパターンのコンパイルは 1 回で済みます。
  • プレフィルタが正しく働く条件：all は全分岐の必須リテラルを合わせたもの、any / not / matches はパターン無しでもマッチしうるので必須リテラルは空とします。こうすることで、プレフィルタがヒットするはずのファイルを誤って除外することはありません。

10. 文字コードとオフセット

SourceFile はファイルをバイト列のまま保持し、EncodingDetector.Detect の判定（明示指定 → BOM → 厳密な UTF-8 → Shift_JIS / EUC-JP のスコア比較）に従ってデコードします。生のバイト列の SHA-256 も記録し、リライト時の楽観ロックに使います。

11. リライト

テンプレートの置換は $$$NAME → $NAME → 名前なしの $$$ の順に行います。CLI では run --rewrite … [--apply] と scan --update-all（ルールの fix）、MCP では rewrite_preview / rewrite_apply がこの処理を使います。

12. ホスト層（CLI / MCP / Native）

CLI（Ag4Cli, System.CommandLine）

  • run（パターン検索・リライト）、scan（YAML ルール）、debug parse|pattern（TreeDumper による木の表示）、mcp、version。
  • --backend tree-sitter|antlr（java / cpp / python）。sgconfig の languageBackends より CLI が優先。
  • -c を省略すると、パスから上に向かって sgconfig.yml を探します（SgConfigLocator.FindUpwards）。CustomLanguageBootstrap.ApplyConfig が languageBackends と customLanguages を適用します。
  • stderr のメッセージには ag4: を付け、スタックトレースは --debug のときだけ出します。
コマンド 0 1 2
run 1 件以上マッチ マッチなし 実行時エラー
scan --error-on 以上の重要度のマッチなし しきい値以上のマッチあり 実行時エラー（ルールが 0 件の場合も含む）

MCP（McpHost, ModelContextProtocol）

ツール 用途
list_languages / describe_language 言語の一覧と、kind 名・パターンルールの情報
dump_syntax_tree コードやパターンの木を表示（TreeDumper）
find_code / find_code_by_rule / scan パターン・ルール・sgconfig による検索
test_match_code_rule ルールをコード片に当てて試す
rewrite_preview 差分の preview（読み取り専用）
rewrite_apply 書き換えを適用する（Destructive。--allow-write を付けたときだけ登録される）

ツールに渡されたパスは、どれも McpContext.ResolvePaths → EnsureUnderRoot で --root の内側にあるかを検査し、外側なら拒否します。パスを省略した場合は root 全体が対象です。

Native（NativeExports, NativeAOT）

const char* ag4_version(void);                       // 解放不要
int  ag4_search(const char* request_json, char** out_json); // 0 = 成功, 1 = エラー JSON, 2 = 引数不正
void ag4_free(char* buffer);                          // out_json は必ずこれで解放

SearchHost.Search がリクエストを検証し（pattern と language は必須、strictness は enum 名）、sources があれば RunPatternOnSources（ディスクを読まない）を、なければ paths の検索を行います。例外はすべて {"error": …} の JSON に変換し、ABI の外に投げません。JSON の (de)serialize は source generator （NativeJsonContext）で行い、AOT でも動くようにしています。ヘッダは samples/gui/include/ag4_native.h、使用例は samples/gui（WinForms / Swing+JNA / tkinter+ctypes）にあります。

14. 拡張ポイント

tree-sitter の文法で言語を追加する

  1. TreeSitter.DotNet に対象文法のネイティブライブラリが入っていることを確認する（無い場合は別途ビルド・同梱が必要）。
  2. TsNative に tree_sitter_<lang> の LibraryImport を追加し、TreeSitterBuiltins に定義（拡張子・ルート kind・PatternContexts・supertype 別名）を足す。
  3. BuiltinLanguages で登録し、ApplyBackend の切替対象にするかどうかを決める。
  4. 使わない文法のネイティブを出力から除くフィルタを更新し、テストと THIRD-PARTY-NOTICES.md を更新する。

ANTLR の組み込み言語を追加する

  1. grammars/<lang>/ に grammars-v4 の .g4 と、必要なら CSharp/*Base.cs と LICENSE を置く。
  2. AstGrepAntlr.Languages.csproj に <Antlr4 Include=…>（Package を指定）と、Base クラスの <Compile Include … Link> を追加する。
  3. IAntlrLanguage を実装する：StartRule、PatternRules（式・文を先に、開始ルールは最後に並べる）、MetaVarVariants、InvokeRule の switch、IsNamedToken。
  4. BuiltinLanguages.CreateRegistry() で登録し、必要なら別名も登録する。
  5. tests/*ParseTests.cs、tests/fixtures/cases/<lang>/、difftest/patterns/<lang>.yml を追加し、THIRD-PARTY-NOTICES.md を更新する。

ANTLR 以外のパーサを使う場合は、CSharp と同じように ILanguage を直接実装し、SyntaxTreeAssembler でアリーナ木を組み立てます。

ビルドせずに追加する／埋め込む

  • sgconfig.yml の customLanguages（samples/dsl）。
  • .NET からは AstGrepAntlr.Core と AstGrepAntlr.Languages を参照して Searcher を直接呼べます。それ以外の言語からは ag4_native を FFI で呼びます。

15. 既知の制約

  • 速度：tree-sitter 既定では本家比おおよそ 4〜5×（Java / C++ / Python）。ANTLR 選択時は 20〜60× 程度まで遅くなることがあります（詳細は REPORT.md）。アリーナ変換と照合のコストは残るため、内訳は tools/AstGrepAntlr.Bench で計測できます。
  • C++（ANTLR 選択時）：CPP14 文法なので、C++17 以降の構文やマクロを多用するコードは解析できないことがあります。tree-sitter 既定では tree-sitter-cpp を使います。
  • 文法による違い：kind 名はバックエンドで異なります（tree-sitter 既定は本家に近い）。ANTLR 選択時は grammars-v4 の名前です（C# / Roslyn は別名で一部を吸収）。
  • ネイティブ RID：tree-sitter 同梱は TreeSitter.DotNet が提供する win/linux/osx の RID に依存します。読めない環境では ANTLR にフォールバックします。
  • .interp 言語：アクションと述語を実行しないので、述語に頼る文法は正しく解析できません。
